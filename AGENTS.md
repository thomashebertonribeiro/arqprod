# Resumo do Projeto Arqprod

## Objetivo
- Evoluir o **Arqprod** (PIM multi-tenant: NestJS + PostgreSQL/JSONB + Redis, React + Tailwind) já em produção na VPS Hostinger. Últimos pedidos concluídos: (1) **"os campos criados devem estar em todos os produtos"** — campos valem para todos os produtos sem vínculo com categoria; (2) **"adicione um campo para gerenciar as categorias"** — aba Categorias em Configurações com adicionar/editar/excluir/hierarquia; (3) **"insira a opção de fazer upload de imagens, formato 1200x1200px rgb jpeg ou png"**; (4) **"desenvolva a opção de ter a ferramenta em pt-br e en"** — i18n completo (seletor PT/EN no Nav, dicionário em `i18n.tsx`, persistência localStorage `arqprod_lang`); (5) **"no card da página de produtos deixe visíveis: Nome, Descrição curta, SKU, EAN, NCM, CEST, Custo"** — campos nativos `ean_gtin`, `ncm`, `cest`, `custo` no produto + colunas no card + edição no detalhe.

- **Comportamentos do backend (aprendidos em teste):** `POST /categories` normaliza slug com **underscores** (`teste_producao`); resposta de POST/PATCH/DELETE categoria = entidade crua (`{id, nome, slug, parentId, ordem, criadoEm}`), não `{data:...}`; DELETE retorna `{id}`; `GET /categories` retorna `{data: [...], meta}` em árvore (`children`); exclusão de categoria é segura — `products.category_id` ON DELETE SET NULL, `category_attributes` e `parent_id` CASCADE/SET NULL.
- **Migrações em produção:** não há node_modules no host (tudo roda em docker) e o `dist` antigo contém `.ts` duplicados (glob `*{.ts,.js}` do TypeORM quebra `migration:run` com "Duplicate migrations"). Método usado: aplicar SQL manualmente via `docker compose exec postgres psql -U arqprod -d arqprod` (ALTER TABLE com `IF NOT EXISTS` idempotente) e registrar em `arqprod_migrations` (INSERT com timestamp 17XXXXXXXXXXXX + nome). Colunas novas do produto: `ean_gtin` varchar(40), `ncm` varchar(12), `cest` varchar(10) (pontuação conta no MaxLength: "6109.10.00" = 10), `custo` numeric(12,2) (driver pg retorna string).
- `GET /attributes` NÃO filtra por chave (só nivel/status/tipo_dado). Campos globais em `GET /products/:id` → `fields` (todos atributos ativos da org, order criadoEm ASC).
- Artefatos de teste locais: `garantia_estendida` (campo ativo, demonstrativo), `Eletrônicos` (categoria raiz). Produção: só `Eletrônicos`. Campo `peso_liquido` criado em produção na demo (ativo).
